## Fixed design

| Stage         | Independent draft families | Purpose                                                  |
| ------------- | -------------------------: | -------------------------------------------------------- |
| Training      |                      1,080 | Six plans, two seats, two futures: 25,920 logical labels |
| Development   |                        216 | Select at most one of three already locked models        |
| Qualification |                        648 | Test the selected unchanged model                        |
| Confirmation  |                        648 | Independent final check, conditional on qualification    |

Each bank balances live maps, own/opponent doctrines and draft pick order. Both physical seats and
repeated futures belong to one independent family. Complete-input duplicates can reuse an executed
fight only with explicit hashed receipts.

Frozen recipes are ridge regression with regularization 100; Extra Trees with 512 trees, depth 10,
minimum leaf size 20 and feature fraction 0.75; and gradient boosting with 256 trees, depth 3, minimum
leaf size 20, learning rate 0.03 and squared-error loss. Random seeds and complete settings are in the
protocol. Each model keeps current unless a distinct proposal predicts at least +0.03 mean score gain.
Highest prediction wins; exact ties select the earliest plan. No post-development refitting or tuning.

Development requires +0.5 pp, a positive family confidence lower bound adjusted for three candidates
(98.3333% two-sided intervals), and nonnegative means for every own doctrine. Select the highest passing
mean, with recipe order breaking ties. Qualification and confirmation each require +0.5 pp, a positive
whole-family 95% lower bound and nonnegative own-doctrine means. Each uses 20,000 registered bootstrap
resamples. No subgroup, alternative model or pooled bank can rescue a failed gate.

Every model choice in a bank must be locked before constructing any actual evaluation enemy setup.
Checks include exact input keys, authoritative legality/funding, unchanged opponents, spellbooks,
raw action/health traces, source identity, independent score reconstruction and Python/Bun inference
parity. Offline scores do not replace current native application, serial latency, first-ready deadline,
state identity or Premium Apply/Undo release checks.
