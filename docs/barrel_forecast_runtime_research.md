The fixed [model mixture](barrel_forecast_model_mixture_research.md) passed fresh strength qualification
(+1.488095 score points, 95% +0.281085 to +2.711640), then failed its unchanged two-AI cost gate. The
complete twelve-case live sample used 661 decisions versus 592 stock; both-driver CPU increased 18.11%.
That failure, all losing cases and the original inactive helper remain immutable. Confirmation is closed.

`barrel-forecast-native-context-live-bounds-implementation-v1` is a separate implementation hypothesis,
not a fitted action/tempo rule. The [registration](evidence/barrel_forecast_runtime_registration_20261117.json)
contains exact source patches, hashes, admission, fixed real-cost protocol and the known slow cases.
Nothing in this experiment changes a serving profile or deploys production.

## Implementation

Carry a read-only sample from the caller's **actual** `scoreCandidates` rollout count through `rollout`
and `simPlayTurn`. Only uniform full R2 under v0.8 constructs it. Actual roots, effective R1, R4 and
non-full probes receive no sample. The allocation-light selector keeps the frozen 50/50 model assignment,
barrel eligibility, both future armies/owners and exact returned decision-array identities. It removes
global research callbacks, duplicate eligibility calculations and forecast-statistics work from the
candidate path. No action, rollout, inference, chance draw, learned weight or scoring rule is added.

The other opt-in allows the existing certified selection-aware loser bound in live mode. It keeps the
original protected actions, pool maxima, replay/rounding margins, conditional fallback protection and
full-observer/material restrictions. It introduces no new pruning threshold. Both private experiment
switches default to false; the frozen actor explicitly scopes the entrant-only or both-driver treatment.
The source patches remain research material, outside the current serving source.

## Passed equivalence admission

The direct selector matched the frozen helper by exact array identity in **95,040 guard combinations**,
without RNG draws. Both selector/activation tests and the existing ten bound tests pass, including
**20,000 stochastic selection matrices**. Default live behavior and every original certification guard
remain protected unless the private live-bound experiment is explicitly enabled.

All **444 full-game input/action/event-trace/outcome controls** pass, independently reconstructed from
raw records: 216 offline controls, 216 live-path controls with an explicitly unexhausted clock, and six
forced-R1 pairs. These reproduce every original 72-case stock/mixture/both result and include all twelve
slow cases. Forced R1 exercised 5,864 projected calls with barrels and no projected sample; full R2
exercised 2,418,166 sample contexts. Actual roots never receive projected metadata. No engine/model or
clock-driven fallback occurred. A controlled clock establishes selection equivalence; it measures no
runtime, latency or independent strength gain.

## Frozen real-clock cost gate

After admission, two isolated nice-19 actors execute **one fight at a time**, using the actual native
v10 reference and candidate source. Equal warmup per implementation precedes each phase. All 72 cases
run offline and with real live deadlines, with stock/mixture/both arm positions counterbalanced:
**464 executions**, including warmup. Source, input, complete trace and outcome checks continue under
real clocks, with zero model/action/timing-fallback failures required.

CPU, wall, complete native/search/outer-neural/support decision total and mean ratios must all be at
most **1.10**, for entrant-only and both-driver use, on offline 72, live 72 **and the original slow twelve**.
The old failing cases cannot be dropped. The fixed cutoff is November 17 at **22:35:37 UTC**; no automatic
retry, extension, intermediate timing selection or subset rescue. Both owned actors receive identical
scheduling requests before warmup and retain Unix nice19. Other workloads remain untouched.

The old failed cost result remains failed regardless of this new implementation. Passing the new
cost gate only opens independent fresh confirmation of the unchanged strategy. It does not establish
production two-vCPU latency, general ranked win rates, final qualification or permission to promote.
